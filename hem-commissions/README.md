# ИС «Комиссии Центра гематологии»

Веб-приложение для ведения внутрибольничных комиссий: составы и приказы, положения и НПА (с мониторингом adilet.zan.kz), графики и повестки заседаний, материалы, электронное голосование, протоколы с простой ЭП, решения и поручения, уведомления, отчёты.

Техническое задание — [docs/TZ.md](docs/TZ.md) (версия 0.3).

## Стек

Python 3.12, Django 5.2, PostgreSQL 16 (для разработки — SQLite), Django REST Framework + OpenAPI, reportlab (PDF), python-docx/docxtpl (DOCX), openpyxl (XLSX), Playwright (проверка НПА), S3-совместимое хранилище, Docker.

## Локальный запуск (разработка)

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python manage.py migrate
.venv\Scripts\python manage.py seed_initial --demo
.venv\Scripts\python manage.py seed_demo_content   # составы, подписанные протоколы, предстоящие заседания
.venv\Scripts\python manage.py runserver
```

Откройте http://127.0.0.1:8000/. Команда `seed_initial --demo` печатает логины демо-пользователей и пароль. Письма (коды подписи, уведомления) в режиме разработки выводятся в консоль сервера.

Проверка НПА на adilet.zan.kz требует браузер: `.venv\Scripts\playwright install chromium`. Без него проверка ставит статус «требует проверки».

## Эксплуатация (Docker)

```bash
cp .env.example .env   # заполнить секреты, SMTP, S3, домен
docker compose up -d --build
docker compose exec web python manage.py seed_initial
docker compose exec web python manage.py createsuperuser
```

Сервисы:
- `web` — приложение (gunicorn, порт 8000; перед ним — обратный прокси с HTTPS);
- `db` — PostgreSQL;
- `worker` — планировщик (`run_scheduler`): закрытие голосований, напоминания, эскалации согласований, напоминания по поручениям и положениям, ежемесячная проверка НПА (1-го числа).

Ручной запуск ежедневных задач: `python manage.py run_daily_jobs` (`--monthly` — вместе с проверкой НПА).

Резервное копирование: ежедневный `pg_dump` и копия бакета S3, хранение не менее 30 дней, проверка восстановления раз в квартал (настраивается средствами дата-центра).

## Структура

| Приложение | Назначение |
|---|---|
| `apps/accounts` | пользователи, вход, блокировка, смена/сброс пароля, одноразовые коды |
| `apps/committees` | комиссии, состав и история, приказы, положения, НПА и мониторинг, справочники, права доступа |
| `apps/meetings` | график, заседания, повестка, предложения в повестку, материалы, присутствие и кворум, приглашённые, транскрипты, iCal |
| `apps/voting` | электронное и заочное голосование (кворум 2/3) |
| `apps/protocols` | протоколы, согласование, особые мнения, подписание, PDF и страница проверки, решения и поручения |
| `apps/notifications` | уведомления (система, e-mail, WhatsApp через n8n), планировщик |
| `apps/reports` | формальный и содержательный отчёты, XLSX/PDF, подпись отчёта |
| `apps/audit` | неизменяемый журнал действий |
| `apps/api` | REST API (`/api/`, документация — `/api/docs/`) |

## Ключевые правила

- Изменения состава вступают в силу с даты подписания приказа.
- Протокол: черновик → согласование (особые мнения — только в этот период) → подпись секретаря → подпись председателя → PDF со штампом и QR.
- Голосование: письмо со ссылкой → вход в личный кабинет → голос. Кворум — не менее 2/3 членов, решение принято при «за» более половины проголосовавших.
- Аудиозаписи хранятся только ссылкой. В КИЛИ и ОСК пациенты указываются только ID из МИС; ВКК данные пациентов не ведёт.
- Сроки в рабочих днях считаются по производственному календарю (Администрирование → Производственный календарь).
